# Deploying TGL to Render + Supabase

One Render web service (Docker) serves everything from a single origin:

```
Browser ──► https://<your-domain>  (Render web service, Dockerfile)
              ├── /               public site (prerendered) + member app (/login, /app/…)
              ├── /admin          admin dashboard
              └── /api/…          FastAPI
                     ├──► Supabase Postgres   (all records)
                     ├──► Supabase Storage    (payment proofs, PRIVATE bucket)
                     └──► Resend              (signup / login / reset emails)
```

Same origin is deliberate: the session cookies are `HttpOnly; Secure;
SameSite=Strict`, which only works when the site and API share an origin.
Accounts and sessions are the app's own (Argon2 + signed cookies) — Supabase
Auth is not used, so there is no Supabase key in the browser at all.

## FREE RENDER DEPLOYMENT

`render.yaml` defines exactly **one** Render resource: a **Free** Docker web
service. There is no Render Postgres, no persistent disk, no background
worker and no cron job — data lives in Supabase (Postgres + Storage) and
email goes through Resend's HTTPS API. Nothing in the Blueprint needs a paid
plan.

1. **Connect GitHub** — Render dashboard → *Account settings → Git
   providers* (or the prompt in step 3) → authorise GitHub and give Render
   access to `roshan-ds-tech/TGL_networking`.
2. **Branch** — use `main`.
3. **Create the Blueprint** — *New → Blueprint* → pick the repository →
   branch `main`. Render reads `render.yaml` and shows one service, `tgl`,
   on the **Free** instance type.
4. **Free resources only** — leave the instance type as *Free*. Do not add a
   disk or upgrade the plan; none is needed.
5. **Environment variables** — Render prompts for the five secrets (values
   come from Supabase and Resend, see §1–§2; never commit them):

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | Supabase *Session pooler* connection string, pasted as shown |
   | `SUPABASE_URL` | `https://<project-ref>.supabase.co` |
   | `SUPABASE_SERVICE_ROLE_KEY` | Supabase service_role / secret key |
   | `PUBLIC_ORIGIN` | **leave empty** — the app then uses Render's own `onrender.com` URL (Render provides it as `RENDER_EXTERNAL_URL`) |
   | `RESEND_API_KEY` | Resend API key |

   `SECRET_KEY` is generated by Render; everything else is set in
   `render.yaml`.
6. **Do not create a Render Postgres database.** Supabase is the database.
   If `DATABASE_URL` is missing, the service deliberately refuses to start
   rather than keep records in a temporary file that would vanish.
7. **Deploy** — *Apply*. The first build takes a few minutes (it builds the
   site, the admin dashboard and the API image). Health check:
   `GET /api/health`.
8. **Find the URL** — the service page shows it, like
   `https://tgl-xxxx.onrender.com`.
9. **`PUBLIC_ORIGIN` = that URL** — already the case if you left it empty
   (the app picks up Render's URL itself). To pin it explicitly, set it in
   the *Environment* tab → *Save* (Render redeploys). It is used in
   password-reset email links.
10. **Custom domain, later** — *Settings → Custom Domains* → add
    `tgl.skykeen.in` and create the CNAME record Render shows at your DNS
    provider. Free services support custom domains with automatic HTTPS.
11. **Switch `PUBLIC_ORIGIN`** to `https://tgl.skykeen.in` once the domain
    shows as verified.

**Create the admin login.** Render's *Shell* is not available on free
instances — and is not needed: the database is Supabase, so run the script
from your own machine against it (single quotes keep `!` in the password
safe in zsh/bash):

```bash
cd backend
DATABASE_URL='<the same session pooler URL>' .venv/bin/python create_admin.py
```

It prompts for the admin email and password (never echoed or stored in
plain text) and applies the same schema and RLS lockdown as the app.

### What "Free" means for this app

| Render Free behaviour | Effect on TGL |
|---|---|
| Sleeps after 15 minutes without traffic; the next visitor waits ~1 minute while it wakes | First page load after a quiet spell is slow. Nothing is lost — all data is in Supabase. |
| 750 free instance-hours per month per workspace | One always-awake service uses ~744 h — within the allowance, but a second free service would compete for it. |
| Filesystem is temporary (wiped on every deploy/restart) | Not used: records → Supabase Postgres, payment proofs → Supabase Storage. |
| No Shell / SSH | Admin is created from your machine (above). |
| Outbound SMTP ports blocked | Not used: Resend is called over HTTPS. |
| Restarts clear in-memory state | Login/registration rate-limit counters reset after a sleep or deploy (they rebuild immediately). Sessions survive — they are signed cookies. |
| One instance | Matches the app's design (in-process rate limiter). |

To remove the sleep, change `plan: free` to `plan: starter` in `render.yaml`
— that is the only line involved, and it is the one that requires payment
details.

**Card prompts.** With this Blueprint nothing in the *project* requires a
paid plan. If Render still asks your account for a card, that is an
account-level verification on Render's side (it can apply to new accounts
regardless of plan) — not something this repository causes or can switch
off. In that case, complete it with Render or use the card-free hosts
documented in `DEPLOY_PYTHONANYWHERE.md` / `DEPLOY_ORACLE.md`.

## 1. Supabase (≈5 minutes)

1. Create a project at <https://supabase.com/dashboard> (region: **Mumbai
   `ap-south-1`** is closest to Bengaluru). Save the database password in a
   password manager.
2. **Database URL** — *Project Settings → Database → Connection string →
   **Session pooler***. Copy it and put your password in it. It looks like
   `postgresql://postgres.<ref>:<password>@aws-0-ap-south-1.pooler.supabase.com:5432/postgres`.
   Use the session pooler: it is IPv4-reachable from Render (the direct
   connection is IPv6-only on new projects).
   Paste it exactly as shown — a password containing `@`, `!` or `:` does
   not need manual percent-encoding; the app handles it. The connection is
   TLS-encrypted (`sslmode=require`, Supabase's default). For full
   certificate verification, download Supabase's CA (*Database → SSL
   Configuration*), add it to the image and set `DATABASE_SSL_ROOT_CERT`.
3. **API** — *Project Settings → API*: copy the **Project URL**
   (`https://<ref>.supabase.co`) and the **service_role / secret** key.
   The service key bypasses all access rules: it goes only into Render's
   environment, never into code, chat, or the frontend.

> **The production Supabase project is already provisioned** — tables,
> RLS lockdown and the private bucket were created and verified on
> 2026-10-05. Re-running is harmless.

Nothing else to click. On first boot the app:

* creates its tables (and adds any missing columns on later deploys),
* **enables Row Level Security on every table with no policies and revokes
  the `anon` / `authenticated` grants** — so Supabase's auto-generated Data
  API exposes nothing even to someone holding the public anon key; the app
  itself connects as the table owner and is unaffected,
* creates the private `payment-proofs` Storage bucket (2 MB limit, images +
  PDF only).

## 2. Resend (email)

Signup, OTP login and password reset codes are emailed via
[Resend](https://resend.com). Verify the sending domain (`skykeen.in`, DNS
records per `docs/P0_IMPLEMENTATION.md`) and create an API key. Without it
the site works but **nobody can verify an account** — the server logs
`RESEND_API_KEY is not set` at boot.

## 3. Render

(Step-by-step for the free plan: see **FREE RENDER DEPLOYMENT** above.)

1. The code is on `main` on GitHub.
2. Render dashboard → **New → Blueprint** → select the repo. Render reads
   `render.yaml` and asks for each secret:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | Supabase session-pooler URL from §1.2 |
   | `SUPABASE_URL` | `https://<ref>.supabase.co` |
   | `SUPABASE_SERVICE_ROLE_KEY` | service_role / secret key |
   | `PUBLIC_ORIGIN` | empty at first (falls back to the `onrender.com` URL); `https://tgl.skykeen.in` once the domain is attached |
   | `RESEND_API_KEY` | from §2 |

   `SECRET_KEY` is generated by Render. Everything else has a value in
   `render.yaml`.
3. Deploy. The health check is `GET /api/health`.
4. **Create the admin login** — from your machine, against Supabase (Shell
   is a paid-instance feature; see *FREE RENDER DEPLOYMENT*):
   ```
   cd backend && DATABASE_URL='<session pooler URL>' .venv/bin/python create_admin.py
   ```
5. **Custom domain** — Render → *Settings → Custom Domains* → add
   `tgl.skykeen.in`, then create the CNAME it shows at your DNS provider.
   Update `PUBLIC_ORIGIN` to match. (The site's canonical/OG URLs already
   point at `https://tgl.skykeen.in`.)

## 4. Verify the live deployment

Run the checks in `scripts/smoke-live.sh <URL>` (no data written), then by
hand on a phone and a laptop:

* `/` renders; `/login`, `/signup`, `/app/networking` deep links load;
  a made-up path shows the TGL 404 page.
* Sign up with a real inbox → code arrives → onboarding → `/app/vertex`.
* Submit one registration with a real screenshot → it appears in `/admin`
  and the screenshot opens there. Then delete that test entry in `/admin`
  (this also deletes the stored file).

## 5. GitHub

Deploy from `main` (Render auto-deploys each push to it — `autoDeploy: true`).
`.env` files, `backend/var/` (local database and uploads) and build output
are git-ignored; only `*.example` files with empty values are committed.

## Operations notes

* **One instance.** Rate limits are in-process (`app/ratelimit.py`); keep the
  service at 1 instance unless they are moved to Redis.
* **Proxy hops.** `TRUSTED_PROXY_HOPS=1` makes rate limits key on the IP
  Render's load balancer saw. After the first deploy, confirm the logs show
  real client IPs rather than one shared address; adjust if Render's edge
  adds another hop.
* **Backups.** Supabase takes daily backups on paid plans; on the free plan,
  schedule `pg_dump` yourself. Proofs live in the Storage bucket.
* **Free plans.** Render Free sleeps after 15 idle minutes (~1 min cold
  start — see the table above); Supabase Free pauses a project after a week
  with no database activity (restore it from the Supabase dashboard). Both
  are fine for launch and testing; upgrade the Render plan if the first-visit
  delay matters during the registration window.
